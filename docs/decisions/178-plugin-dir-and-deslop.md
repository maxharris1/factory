# #178: pstack agents by home install, deslop vendored, and the rules file

Choices the builder made for issue #178 (T07c). No product question is open. Each one says what would change it.

- **Decision:** Claude gets pstack's two agents from a home install, not from `--plugin-dir`. A local `orch install-skills` symlinks each pinned file under `skills/pstack/agents/` and `skills/pstack/docs/` to the same path under `~/.claude/`, so `~/.claude/agents/poteto-agent.md` and `~/.claude/agents/comment-sicko.md` resolve to the pin. Claude jobs keep their current launch argv. Evidence: T03c (#176) added the `--plugin-dir` probe code and fake-tree tests only. `docs/skill-loading.md` still says "No live `--plugin-dir` rows yet", and its note that the `pstack:` prefix "depends on Claude naming the plugin after its directory, since pstack ships no `.claude-plugin/plugin.json`" is untested on a live Claude. The ticket takes `--plugin-dir` only when the evidence shows it works, and none does. The live rows from `bin/skill-probe run --plugin-dir` (an operator step) could reopen this. A follow-up ticket would then change the waiter argv and remove the home install.
- **When:** 2026-11-14 ET, by Factory decided (technical)
- **Source:** https://github.com/maxharris1/factory/pull/242

- **Decision:** The installed agents keep their pstack names, `poteto-agent` and `comment-sicko`, with no prefix. The Claude adapter (`skills/pstack/docs/harness/claude-code.md`, Subagent fields) maps them to `pstack:poteto-agent` and `pstack:comment-sicko`, the names a plugin gets, so `skills/factory/factory-builder/SKILL.md` has a difference row naming the unprefixed names. `~/.claude/docs/` mirrors pstack's `docs/`, so `~/.claude` has the `skills/`, `agents/` and `docs/` layout that `<pstack>` stands for in a skill read from `~/.claude/skills/`. A file already there that is not a symlink into a `skills/pstack` checkout is refused and nothing is written. A cloud install (`--cloud`) adds no agents, docs or rules file.
- **When:** 2026-11-14 ET, by Factory decided (technical)
- **Source:** https://github.com/maxharris1/factory/pull/242

- **Decision:** The `deslop` skill is vendored from cursor-team-kit. License: `cursor-team-kit/LICENSE` in github.com/cursor/plugins is MIT ("Copyright (c) 2026 Cursor"), and its `.cursor-plugin/plugin.json` also says `"license": "MIT"`. MIT allows copying with the notice, so `skills/cursor-team-kit/LICENSE` ships beside `skills/cursor-team-kit/deslop/SKILL.md`. Both files come from cursor/plugins commit `3dbd22ff12742fb28c9700b9760baa29ed41dc13` unchanged. The git blob of `SKILL.md` is `1b3827c7f991182149a7abda696af43ff8f17a12` at that commit and in this tree. `skills/skills.lock` pins both files by sha256 in a new `kit` section (D22). `verify_pin` and `install-skills` refuse a tree that differs from the lock. `deslop` installs beside `poteto-mode` in each harness skills folder. No other cursor-team-kit file is vendored.
- **When:** 2026-11-14 ET, by Factory decided (technical)
- **Source:** https://github.com/maxharris1/factory/pull/242

- **Decision:** A local `orch install-skills` writes `~/.claude/rules/pstack-models.md` from `python -m lib.pstack_models rules` (T10, #160), on the deploy that installs this ticket, not earlier. The text goes to a temp file in the same folder and is moved in with `os.replace`, so a job never reads half a file. Claude reads rules when a session starts, so a running job keeps the text it started with. The file carries no version stamp (D34). The installer owns it when its first line is the generated header line ("# pstack model configuration. ... Generated from config/pstack-models.yml by lib/pstack_models.py ..."). It replaces an owned file whole. It refuses a hand-written one (for example from `setup-pstack`) and then writes nothing.
- **When:** 2026-11-14 ET, by Factory decided (technical)
- **Source:** https://github.com/maxharris1/factory/pull/242

- **Decision:** Rolling back this ticket also removes the rules file (SF-11). On each device and for each bot, run `orch install-skills --remove-claude-extras` (add `--home PATH` for a home other than `~`) from the deployed checkout **before** the revert deploys, because the reverted code has no such flag. It removes `~/.claude/rules/pstack-models.md` when the installer owns it, plus every symlink under `~/.claude/agents/` and `~/.claude/docs/` that points into a `skills/pstack` checkout. Then it removes any of those folders left empty. Other agents and the installed skills stay. If the revert already deployed, run `rm ~/.claude/rules/pstack-models.md ~/.claude/agents/poteto-agent.md ~/.claude/agents/comment-sicko.md` and `rm -r ~/.claude/docs` by hand. Check first that `~/.claude/docs` holds only links into `skills/pstack`.
