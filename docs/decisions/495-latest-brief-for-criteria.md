# 495: one brief for the builder and the reviewer

- **Decision:** The latest trusted brief (`kind=brief`, `from=grok-bot`, `role=orchestrator`, from a login `trusted_logins` lets speak for grok-bot) supplies both the builder's brief and the reviewer's acceptance criteria. The poll picks it once with `lib.evidence.criteria.canonical_brief` and keeps it as `TrackedTicket.brief_comment`; `TrackedTicket.brief` and the review bundle's criteria both come from that comment. On Linear the poll picks from the Linear comments only, as before. With no trusted brief, the criteria come from the source issue's body, then the PR description on a `ready_starts_review` project. A GitHub source issue's body costs one read per PR head, made only when the ticket has no trusted brief; the PR description and the Linear description come from reads the poll already makes. When no source has text, the bundle says so in one fixed sentence.
- **When:** 2026-11-16, by Factory decided (technical)
- **Source:** https://github.com/maxharris1/factory/issues/495 and PR #520, following #54 (PR #444), which chose the latest brief for the builder because a re-brief after answered questions carries the new scope. Before this change the reviewer took the first brief, so with two briefs it could mark criteria the builder never saw.
